# PRD.md — 요금제 추천·구독 서비스

색·글자·간격·컴포넌트 같은 비주얼 규칙은 이 문서에 쓰지 않는다. 모든 비주얼 규칙은 **Design.md를 따른다.**

---

## 1. 목적

### 한 줄 정의

요금제 추천·구독은 **월말 전에 데이터가 떨어지는 고객**이 **데이터량·속도 제한 여부·실제 월 납부액을 비교해 맞는 요금제를 골라** **통신사 모바일 웹을 벗어나지 않고 바로 신청**하는 모바일 웹 서비스다.

### 해결할 문제

1. 출퇴근길에 영상을 보는 고객은 매달 20일쯤 데이터가 다 떨어진다.
2. 고객은 통신사 앱·홈페이지의 요금제 페이지를 먼저 열지만, 20개가 넘는 요금제 목록에서 몇 개만 눌러보다가 포털 검색("데이터 무제한 요금제 추천")이나 커뮤니티 후기로 이탈하고, 정보가 너무 많아 결국 변경을 포기한다.
3. 고객은 두 가지를 판단하지 못한다.
   - "무제한"이라는 이름만으로는 기본 데이터 소진 후 속도가 제한되는 요금제인지, 속도 제한이 없는 요금제인지 구분할 수 없다. ("무제한이라면서 왜 느려져요?")
   - 정가·할인가·프로모션가가 함께 표시되어 매달 실제로 내는 금액과 24개월 할인 종료 후 금액을 알 수 없다. ("그래서 제가 매달 실제로 내는 돈이 얼마예요?")

### 용어

- **매달 내는 금액**: 할인이 적용된 매달 납부 금액이다. 이 문서와 화면에서는 이 용어로 통일한다. 요금제 데이터 표의 "월 요금" 열, `monthly_price`, Card/Price 컴포넌트가 가리키는 값도 같은 금액이다.
- **구독 신청**: 사용자가 이 서비스에서 요금제를 신청하는 행위의 이름이다. "요금제 변경"이라는 표현은 쓰지 않는다.

## 2. 대상 사용자

### 유저 스토리

- **US1.** 출퇴근길에 영상을 보는 고객으로서, 월말까지 데이터를 쓰기 위해 데이터량을 기준으로 요금제를 비교하고 싶다.
- **US2.** 20개가 넘는 요금제 앞에서 선택이 어려운 고객으로서, 비교할 후보를 줄이기 위해 내 상황에 맞는 요금제만 추려 보고 싶다.
- **US3.** "무제한" 요금제를 보는 고객으로서, 월말에 속도가 느려지지 않기 위해 기본 데이터 소진 후 속도 제한이 있는지 확인하고 싶다.
- **US4.** 여러 가격이 함께 적힌 요금제를 보는 고객으로서, 실제 부담을 알기 위해 매달 내는 금액과 24개월 할인 종료 후 금액을 확인하고 싶다.
- **US5.** 요금제를 고른 고객으로서, 포털이나 커뮤니티로 나가지 않고 이 서비스 안에서 바로 구독 신청하고 싶다.

### 사용자 상황 (도메인 스토리 요약)

출퇴근길에 영상을 보는 고객 A는 이번 달에도 20일쯤 데이터가 다 떨어졌다. A는 통신사 앱의 요금제 페이지를 열었지만 20개가 넘는 요금제 중 몇 개만 눌러보았다. "무제한" 요금제가 소진 후 속도 제한이 있는지 이름만으로 알 수 없었고, 정가·할인가·프로모션가가 함께 적혀 있어 매달 내는 금액과 24개월 할인 종료 후 금액도 알 수 없었다. A는 포털 검색과 커뮤니티 후기를 찾아보았지만 정보가 너무 많아 요금제 변경을 포기했다.

## 3. 화면 목록

지켜야 할 것: ① 화면 4개(3~6개 범위) ② "신청(저장)" 흐름 1개 포함(구독 신청 → 신청 완료) ③ 샘플 라이브러리 컴포넌트와 토큰으로만 구성(Design.md를 따른다)

### 화면 구조

| 순서 | 화면 이름 | 라우트 | 한 줄 역할 | 해결하는 유저 스토리 |
|---|---|---|---|---|
| 1 | 요금제 목록 | `/plans` | 요금제별 데이터량·소진 후 속도·매달 내는 금액을 한 카드에 표시해 후보를 고르게 한다 | US1, US2, US3, US4 |
| 2 | 요금제 상세 | `/plans/[id]` | 선택한 요금제의 매달 내는 금액, 할인 종료 후 금액, 소진 후 속도를 확인하고 신청으로 넘어가게 한다 | US3, US4, US5 |
| 3 | 구독 신청 | `/apply` | 신청 정보를 입력받아 구독 신청을 저장한다 | US4, US5 |
| 4 | 신청 완료 | `/complete` | 저장된 신청 내역을 표시한다 | US5 |

### 주요 흐름

```
요금제 목록 (/plans) → 요금제 상세 (/plans/[id]) → 구독 신청 (/apply) → 신청 완료 (/complete)
```

되돌아가는 흐름:

- 요금제 상세 → 뒤로(icon/arrowLeft) → 요금제 목록 (`/plans`)
- 구독 신청 → 뒤로(icon/arrowLeft)가 취소 역할을 한다 → 요금제 상세 (`/plans/[id]`). 별도 취소 버튼은 두지 않는다.
- 신청 완료 → 뒤로(icon/arrowLeft) → 요금제 목록 (`/plans`). 이전 기록을 대체해 구독 신청(`/apply`)으로 돌아가지 않는다.
- 신청 완료 → '요금제 더 보기' → 요금제 목록 (`/plans`)

## 4. 화면별 기능

### 4-1. 요금제 목록 (`/plans`)

필수 기능:

1. **요금제 카드 (Card/Plan)** — US1, US3, US4
   - 표시 항목: 요금제 이름 · 기본 데이터량 · 소진 후 속도("소진 후 ○Mbps로 제한" 또는 "속도 제한 없음") · 매달 내는 금액 1개 · 할인 종료 후 금액("25개월째부터 ○원") · '자세히' 버튼
   - 기본 상태: 요금제 데이터(아래 표)의 p01~p04 4개 카드를 모두 표시한다. 기본 정렬은 매달 내는 금액이 낮은 순(p01, p02, p03, p04)이다.
   - 할인이 없는 요금제는 할인 종료 후 금액 줄을 표시하지 않는다.
   - 정가·할인가·프로모션가를 한 카드에 나란히 표시하지 않는다. Card/Plan의 `Original`(정가) 속성은 사용하지 않는다(끈다).
   - Card/Plan 속성 매핑: 추천 Tag는 `Badge`, "24개월 할인" Chip은 `Promo`/`Sale`로 표시한다. 해당하지 않는 카드는 속성을 끈다.
2. **요금제 필터 (FilterChip)** — US2
   - 표시 항목: '전체' 칩과 조건 칩. 조건 칩은 데이터량 구간과 속도 제한 여부 두 종류이며, 칩 라벨과 데이터량 구간 경계값은 **확인 필요**
   - 기본 상태: '전체' 칩이 선택되어 있고 4개 카드가 모두 표시된다.
   - 동작: 한 번에 칩 1개만 선택할 수 있다(단일 선택). 칩을 누르면 조건에 맞는 카드만 남고, 선택한 칩이 선택 상태로 바뀐다. '전체'를 누르면 4개 카드로 돌아간다.
   - 조건에 맞는 카드가 0건이면 카드 영역에 "조건에 맞는 요금제가 없어요."를 표시하고, '전체' 칩으로 돌아갈 수 있다.
3. **추천 표시 (Tag)** — US2
   - 표시 항목: 추천 Tag
   - 기본 상태: p02(데일리 50GB) 카드 1개에만 표시한다. 필터로 p02가 숨겨지면 추천 Tag도 함께 숨겨진다.
4. **할인 프로모션 표시 (Chip)** — US4
   - 표시 항목: "24개월 할인" 문구
   - 기본 상태: 24개월 할인이 있는 요금제 카드에만 표시한다.
5. **상세 이동 ('자세히' Button)** — US5
   - 동작: 누르면 해당 요금제의 요금제 상세(`/plans/[id]`)로 이동한다. 카드의 버튼 외 영역을 눌러도 동작하지 않는다.
6. **헤더·로고 (Header + Logo)**
   - 표시 항목: 화면 제목(Header `root` 유형), U+ 로고

로딩·빈·에러 상태: 화면 단위 로딩·에러 화면은 범위 밖이다(screens.md에 정의되지 않음). 필터 결과 0건 처리는 위 2번을 따른다.

### 4-2. 요금제 상세 (`/plans/[id]`)

필수 기능:

1. **헤더 (Header + icon/arrowLeft)**
   - 표시 항목: 요금제 이름, 뒤로 아이콘
   - 동작: 뒤로 아이콘을 누르면 요금제 목록(`/plans`)으로 이동한다.
2. **월 요금 (Card/Price)** — US4
   - 표시 항목: "매달 내는 금액" 1개(할인 적용 금액), 그 아래 "25개월째부터 ○원"(할인 종료 후 금액)
   - 기본 상태: 할인이 없는 요금제는 매달 내는 금액만 표시하고 할인 종료 후 줄은 표시하지 않는다.
   - 정가·할인가·프로모션가 3개를 함께 표시하지 않는다.
3. **기본 제공 항목 (List/Row)** — US1, US3
   - 표시 항목: 기본 데이터량, 소진 후 속도("소진 후 ○Mbps로 제한" 또는 "속도 제한 없음")
   - 통화·문자 등 그 밖의 행: **확인 필요**
4. **추천 표시 (Tag)**
   - 기본 상태: 목록에서 추천 Tag가 붙은 요금제일 때만 표시한다.
5. **포함 혜택 (List/Row, Type=check)**
   - 표시 항목: **확인 필요** (인터뷰에서 혜택 내용이 나오지 않음). 선택 동작이 없는 정보 표시이므로 OptionItem 대신 List/Row(check)를 쓴다.
   - 기본 상태: 표시할 혜택이 없으면 섹션 제목을 포함해 섹션 전체를 숨긴다.
6. **신청 영역 (BottomCTA + '구독 신청하기' Button)** — US5
   - 표시 항목: 매달 내는 금액, '구독 신청하기' 버튼
   - 동작: 버튼을 누르면 선택한 요금제 id를 가지고 구독 신청(`/apply`)으로 이동한다.
7. **존재하지 않는 요금제 id**
   - 동작: p01~p04에 없는 id로 진입하면 "요금제를 찾을 수 없어요." 안내문과 '목록으로' 버튼을 표시한다. 버튼을 누르면 요금제 목록(`/plans`)으로 이동한다.

로딩·빈·에러 상태: 화면 단위 로딩·에러 화면은 범위 밖이다(screens.md에 정의되지 않음). 잘못된 id 처리는 위 7번을 따른다.

### 4-3. 구독 신청 (`/apply`)

필수 기능:

1. **헤더 (Header + icon/arrowLeft)**
   - 동작: 뒤로 아이콘이 취소 역할을 한다. 누르면 요금제 상세(`/plans/[id]`)로 이동하고, 입력한 이름·휴대폰 번호·동의 체크는 유지하지 않고 초기화한다.
2. **선택한 요금제 요약 (List/Row)** — US4
   - 표시 항목: 요금제 이름, 매달 내는 금액, 할인 종료 후 금액(할인 있는 요금제만)
   - 요금제 id 없이, 또는 p01~p04에 없는 id로 진입하면 "요금제를 찾을 수 없어요." 안내문과 '목록으로' 버튼을 표시한다. 버튼을 누르면 요금제 목록(`/plans`)으로 이동한다.
3. **신청 정보 입력 (Input)** — US5
   - 표시 항목: 이름 입력란, 휴대폰 번호 입력란
   - 기본 상태: 두 입력란 모두 비어 있다.
   - 입력 규칙:

| 입력란 | 규칙 | 오류 표시 시점 |
|---|---|---|
| 이름 | 앞뒤 공백을 제거한 뒤 2~20자의 한글 또는 영문 | 입력란을 벗어날 때 |
| 휴대폰 번호 | 숫자만 입력할 수 있다(숫자 외 문자는 입력되지 않음). "010"으로 시작하는 11자리. 하이픈이 포함된 값을 붙여넣으면 하이픈을 제거한다. | 입력란을 벗어날 때 |

4. **개인정보 수집·이용 동의 (Checkbox)** — US5
   - 기본 상태: 체크되지 않은 상태
   - 동의 문구 옆에 '내용 보기'를 두고, 누르면 아래 항목을 보여 준다.
     - 수집 항목: 이름, 휴대폰 번호
     - 이용 목적: 구독 신청 접수와 신청 결과 안내
     - 보관 기간: **확인 필요**
   - 만 14세 미만 사용자의 처리 방식: **확인 필요**
5. **신청하기 (BottomCTA + '신청하기' Button)** — US5
   - 기본 상태: 이름·휴대폰 번호가 비어 있거나 동의가 체크되지 않으면 버튼이 비활성 상태다.
   - 동작: 세 조건을 모두 채우면 버튼이 활성화된다. 누르면 Subscription 1건을 저장하고 신청 완료(`/complete`)로 이동한다.
   - 저장 중: 버튼을 비활성으로 바꾸고 "신청 중이에요" 문구를 표시한다. 저장이 끝나기 전의 추가 탭은 무시한다(중복 제출 방지).
   - 저장 실패 시: 입력값과 동의 체크를 유지하고, 버튼을 다시 활성화해 재시도할 수 있게 한다. 저장 응답을 기다리는 최대 시간은 **확인 필요**
   - 같은 휴대폰 번호·같은 요금제의 반복 신청도 막지 않는다(별도 신청 1건으로 저장).

오류 상황과 안내 문구:

| 상황 | 안내 문구 | 표시 위치 |
|---|---|---|
| 이름 입력란을 비운 채 다음 입력란으로 이동 | 이름을 입력해 주세요. | 이름 입력란 아래 |
| 이름이 2~20자의 한글 또는 영문이 아님 | 이름은 2~20자의 한글 또는 영문으로 입력해 주세요. | 이름 입력란 아래 |
| 휴대폰 번호가 "010"으로 시작하는 숫자 11자리가 아님 | 휴대폰 번호 11자리를 숫자로 입력해 주세요. | 휴대폰 번호 입력란 아래 |
| 저장 실패 | 신청을 저장하지 못했어요. 다시 시도해 주세요. | 신청하기 버튼 위 (Design.md에 이 오류 영역에 해당하는 컴포넌트가 없어 Variant 추가가 필요할 수 있음. **확인 필요**) |

### 4-4. 신청 완료 (`/complete`)

필수 기능:

1. **완료 표시 (icon/doneMark)** — US5
   - 표시 항목: 완료 아이콘, "구독 신청이 완료됐어요" 문구
2. **신청 내역 (List/Row)** — US5

   - 기본 상태: 방금 저장한 Subscription 값으로 채운다. 값을 `/apply`에서 `/complete`로 넘기는 방식은 개발 합의가 필요하다(**확인 필요**).
   - 신청자 이름은 일부를 마스킹해 표시한다(예: 첫 글자만 보이고 나머지는 `*`).
   - 방금 저장한 값이 없는 경우(새로고침, 주소로 직접 진입)에는 요금제 목록(`/plans`)으로 이동한다.
3. **'요금제 더 보기' (BottomCTA + Button)**
   - 동작: 누르면 요금제 목록(`/plans`)으로 이동한다.
4. **헤더 (Header + icon/arrowLeft)**
   - 표시 항목: 화면 제목, 뒤로 아이콘
   - 동작: 뒤로 아이콘을 누르면 요금제 목록(`/plans`)으로 이동한다. 이전 기록을 대체하므로 구독 신청(`/apply`)으로 돌아가지 않는다.

로딩·빈·에러 상태: 화면 단위 로딩·에러 화면은 범위 밖이다(screens.md에 정의되지 않음). 값이 없는 경우는 위 2번을 따른다.

### 어기면 안 되는 것 (O/X 판정 규칙)

1. 요금제 목록에 요금제 카드가 정확히 4개(p01~p04) 있다.
2. 추천 Tag는 요금제 목록에 1개만 있다.
3. 요금제 카드와 요금제 상세에는 금액이 "매달 내는 금액" 1개와 "할인 종료 후 금액" 최대 1개만 있다. 정가·할인가·프로모션가 3개가 함께 표시되지 않는다.
4. 할인 종료 후 금액은 24개월 할인이 있는 요금제(p03)에만 있다.
5. 이름에 "무제한"이 들어간 요금제(p03, p04)의 카드와 상세에는 "소진 후 ○Mbps로 제한" 또는 "속도 제한 없음" 중 하나가 있다.
6. 구독 신청 화면에서 이름·휴대폰 번호가 비어 있거나 동의가 체크되지 않으면 '신청하기' 버튼이 눌리지 않는다.
7. 신청 완료 화면의 요금제 이름과 매달 내는 금액이 구독 신청 화면에서 선택한 요금제와 같다.
8. 요금제 목록에서 조건 칩을 누르면 조건에 맞는 카드만 남고 선택한 칩 1개만 선택 상태가 된다. '전체' 칩을 누르면 카드 4개가 다시 표시된다.
9. 요금제 목록의 카드는 매달 내는 금액이 낮은 순(p01, p02, p03, p04)으로 표시된다.
10. 구독 신청 화면의 뒤로 아이콘은 요금제 상세(`/plans/[id]`)로 이동하고, 이때 입력값은 초기화된다.
11. 신청 완료 화면의 뒤로 아이콘과 '요금제 더 보기'는 모두 요금제 목록(`/plans`)으로 이동하며, 구독 신청(`/apply`)으로 돌아가지 않는다.
12. 신청 완료 화면에서 새로고침하거나 주소로 직접 진입하면 요금제 목록(`/plans`)으로 이동한다.
13. 존재하지 않는 요금제 id로 요금제 상세나 구독 신청에 진입하면 안내문과 '목록으로' 버튼이 표시된다.
14. 구독 신청의 오류 안내 문구는 오류 상황 표에 적힌 위치에 표시된다.
15. 저장 중에는 '신청하기' 버튼이 눌리지 않으며, 저장이 실패해도 입력값은 유지된다.

## 5. 데이터

```yaml
Subscription:          # 구독 신청 1건. 저장소(서버 또는 가상 저장소)는 개발 합의 필요(확인 필요)
  id:                  string   # 신청 번호. 저장 시 생성. 형식은 개발 합의 필요(확인 필요)
  name:                string   # 신청자 이름. 앞뒤 공백 제거 후 2~20자 한글·영문
  phone:               string   # 휴대폰 번호. 하이픈 없는 숫자 11자리, "010"으로 시작
  plan_id:             string   # 요금제 id (p01 | p02 | p03 | p04)
  monthly_price:       number   # 신청 시점의 매달 내는 금액(원). 할인이 적용된 금액
  agreed_privacy:      boolean  # 개인정보 수집·이용 동의. true일 때만 저장
  created_at:          datetime # 신청 일시. 저장 시 생성. ISO 8601로 저장. 화면 표시 형식과 시간대는 확인 필요

Plan:                  # 요금제 (4장 요금제 데이터 표와 같은 값)
  id:                  string   # p01 ~ p04
  name:                string
  monthly_price:       number   # 매달 내는 금액(원)
  data_gb:             number | null  # 기본 데이터량(GB). 무제한이면 null
  data_label:          string   # 화면 표시 문구. "10GB" | "50GB" | "기본 100GB" | "무제한"
  throttle_mbps:       number | null  # 소진 후 제한 속도(Mbps). 제한 없으면 null
  price_after_discount: number | null # 할인 종료 후 월 요금(원). 할인 없으면 null
  discount_months:     number | null  # 할인 기간(개월). 할인 없으면 null
  description:         string   # 한 줄 설명
  recommended:         boolean  # 추천 Tag 표시 여부. p02만 true
```

표시 문구 규칙:

- 소진 후 속도: `throttle_mbps`에 값이 있으면 "소진 후 {값}Mbps로 제한", null이면 "속도 제한 없음"으로 표시한다.
- 할인 종료 후 금액: `discount_months`에 값이 있으면 "{discount_months + 1}개월째부터 {price_after_discount}원"으로 표시한다(p03은 "25개월째부터 69,000원").
